# VK&S Website — Staff Content Guide

This guide is for whoever updates content on **www.cavks.in**.
You do not need to know how to code. Everything below can be done from
your web browser at **github.com**.

---

## How the website is wired (one-paragraph version)

The website is a set of static files (HTML, CSS, JS) plus three small
content files in JSON format:

| What you edit | File / folder | Where it appears on the site |
|---|---|---|
| **Monthly bulletin PDFs** | `bulletins/` folder + auto-generated `bulletins-manifest.json` | Insights → Monthly Bulletins |
| **Articles & alerts** | `publications.json` | Insights → Articles & Alerts |
| **Job openings** | `job-openings.json` | Careers page |
| **Page text / images / design** | The `.html`, `.css` files | Whole site (do not edit unless you know what you are doing) |

Everything except design is data-driven. Edit the data → the page updates.

---

## How publishing works (GitHub Pages)

The repo on **github.com** is the source of truth.
The moment you commit a change on github.com, GitHub Pages rebuilds the live
site at **www.cavks.in** within about 30–60 seconds. There is no separate
"publish" button. Save = published.

Two automatic safety nets are in place:

1. **Bulletin sync** — every time you upload or remove a PDF in the
   `bulletins/` folder, a GitHub Action regenerates `bulletins-manifest.json`
   and commits it back. You do not edit this file manually.

2. **JSON validator** — every time `publications.json` or `job-openings.json`
   is changed, a GitHub Action checks that the file is still valid. If you
   accidentally delete a comma, you will see a **red ❌** next to your commit
   on github.com and receive an email. The previous (valid) version stays
   live until you fix the new one.

## 1. Publish a new monthly bulletin (PDF) — 30-second job

This is the most common task. **You do not edit any JSON for this.**

### Steps (on github.com)

1. Go to the repo on github.com.
2. Click into the `bulletins` folder.
3. Click **Add file → Upload files**.
4. Drag and drop the new PDF.
5. Make sure the filename follows this pattern:
   `Month-YYYY.pdf` — for example `April-2026.pdf`, `January-2027.pdf`.
   - Use the full month name with a capital first letter
   - Use a hyphen between month and year
   - No spaces in the filename
6. Scroll down, type a short message like *"Add April 2026 bulletin"*,
   click **Commit changes**.

### What happens automatically

- GitHub Action **Sync Bulletins Manifest** runs (you can watch it under
  the **Actions** tab). About 20 seconds.
- It rewrites `bulletins-manifest.json` and commits the change back.
- GitHub Pages rebuilds the site. About 30 seconds.
- Total: roughly 1 minute from upload to live.

### To remove a bulletin

1. Open the `bulletins/` folder.
2. Click on the PDF, click the trash icon, commit.
3. The Action auto-removes it from the manifest.

### To rename a bulletin

Easiest: delete the wrongly-named file, upload it again with the correct
name. The Action handles the rest.

## 2. Add or edit an article / alert

Articles live in **`publications.json`**. The JSON validator workflow will
flag any syntax mistakes, but the easiest way to avoid mistakes is to **copy
an existing article and edit only the text**.

### To add a new article (on github.com)

1. Open `publications.json` in the repo.
2. Click the pencil ✏ icon (top-right) to edit.
3. Right after the opening `[` on line 1, paste a new block. Copy this
   template and fill in your text:

```json
  {
    "slug": "short-name-with-hyphens",
    "title": "The Article Title",
    "tag": "GST & Indirect Tax",
    "excerpt": "One- or two-line summary that shows on the card.",
    "date": "April 2026",
    "read": "6 min read",
    "author": "VK&S Team",
    "content": [
      {
        "type": "paragraph",
        "text": "Opening paragraph of the article."
      },
      {
        "type": "heading",
        "text": "Section heading"
      },
      {
        "type": "list",
        "items": [
          "First bullet point.",
          "Second bullet point."
        ]
      },
      {
        "type": "paragraph",
        "text": "Closing paragraph."
      }
    ]
  },
```

4. Important: put a **comma** at the end of the closing `}` so the next
   article in the list is still valid.
5. Scroll down, write a short commit message, click **Commit changes**.

### Field rules

| Field | What it does | Example |
|---|---|---|
| `slug` | Unique link name. Lowercase, hyphens, no spaces. | `gst-annual-return-2026` |
| `title` | Headline on the card and at the top of the article. | `GST Annual Return Points for FY 2025-26` |
| `tag` | Category. The filter buttons on the Insights page are built automatically from these. | `GST & Indirect Tax`, `Direct Tax`, `IBC & Insolvency` |
| `excerpt` | 1-2 line teaser shown on the listing card. | |
| `date` | Display date — written as you want it shown. | `April 2026` |
| `read` | Estimated reading time. | `6 min read` |
| `author` | Usually `VK&S Team`. | |
| `content` | The article body, made of blocks. See below. | |

### Article body — the three block types

```json
{ "type": "paragraph", "text": "Plain paragraph text." }
```

```json
{ "type": "heading", "text": "Section heading" }
```

```json
{ "type": "list", "items": ["First point.", "Second point.", "Third point."] }
```

You can mix as many of each as you want, in any order.

### To edit an existing article

1. Open `publications.json`.
2. Click the pencil ✏ icon.
3. Find the article (search by title with **Ctrl + F**).
4. Edit only the text. Do not touch curly braces, square brackets, commas,
   or quotation marks.
5. Commit.

### To delete an article

1. Open `publications.json`, click pencil ✏.
2. Delete from the article's opening `{` to its closing `}`.
3. If a comma is left dangling before the closing `]`, remove it.
4. Commit.

If you make a mistake, the JSON validator workflow will fail with a
red ❌ and tell you which line. Just fix it and commit again.

## 3. Add, hide or edit a job opening

Jobs live in **`job-openings.json`**. Same idea — copy an existing block,
edit, commit.

### To post a new opening (on github.com)

1. Open `job-openings.json`, click pencil ✏.
2. Paste this block right after the opening `[`:

```json
  {
    "status": "open",
    "role": "Senior GST Associate",
    "practice": "GST & Indirect Tax",
    "location": "Nagpur",
    "type": "Full-time",
    "experience": "2+ years",
    "priority": "Immediate",
    "summary": "Short one-paragraph description of what the role involves.",
    "responsibilities": [
      "First responsibility.",
      "Second responsibility.",
      "Third responsibility."
    ],
    "requirements": [
      "First requirement.",
      "Second requirement."
    ]
  },
```

3. Edit all fields with the real role details.
4. Make sure there is a **comma** after the closing `}` if other jobs follow.
5. Commit.

### Field rules

| Field | What it does | Allowed values |
|---|---|---|
| `status` | Show or hide the role on the site without deleting it. | `open` or `closed` |
| `role` | Job title. | Free text |
| `practice` | Practice area (used as a label on the card). | Free text |
| `location` | Office location. | Usually `Nagpur` |
| `type` | Employment type. | `Full-time`, `Articleship`, etc. |
| `experience` | Required experience. | `Fresher`, `2+ years`, etc. |
| `priority` | Short label shown as a chip. | `Immediate`, `Open`, `Selective` |
| `summary` | One paragraph for the job card. | |
| `responsibilities` | List of bullet points. | |
| `requirements` | List of bullet points. | |

### To hide (not delete) a job

Change one word:

```diff
- "status": "open",
+ "status": "closed",
```

The role disappears from the Careers page but stays in the file for later.

### To re-open it

Change `closed` → `open` and commit.

### To delete a job permanently

Remove the full block from `{` to `}`. If a stray comma is left before the
final `]`, remove it.

## 4. What to do if something looks broken

### The Insights or Careers page section is blank

This usually means the JSON file has a typo (missing comma, unmatched
quote, etc.). Steps to fix:

1. Go to the **Actions** tab on the repo.
2. Look for the most recent run of **Validate Content JSON**.
3. If it has a red ❌, click into it. The log will tell you which file
   and which line is broken.
4. Open the file, click pencil ✏, fix the issue, commit.
5. The validator runs again. When it shows a green ✓, the page is fine.

### A bulletin doesn't appear

1. Go to the **Actions** tab.
2. Check the most recent **Sync Bulletins Manifest** run.
3. If it failed: most often the PDF filename does not match the
   `Month-YYYY.pdf` pattern (e.g. has a space, or wrong capitalisation).
   Rename the PDF and re-upload.

### I want to undo a change

Every commit on github.com has a **Revert** button. Click into any commit
on the repo, click **Revert**, confirm. The site rolls back in about a
minute.

## 6. Quick reference

| I want to… | Open file / folder | What to do |
|---|---|---|
| Publish a new monthly bulletin | `bulletins/` | Drag-drop the PDF, commit. Manifest updates itself. |
| Hide a bulletin | `bulletins/` | Delete the PDF, commit. Manifest updates itself. |
| Add an article / alert | `publications.json` | Copy a block at the top of the list, edit, commit. |
| Edit an article | `publications.json` | Find the article, edit text only, commit. |
| Delete an article | `publications.json` | Remove the block, fix trailing comma, commit. |
| Post a new job | `job-openings.json` | Copy a block at the top of the list, edit, commit. |

| Re-open a job | `job-openings.json` | Change `"closed"` back to `"open"`. |
| Delete a job permanently | `job-openings.json` | Remove the block, fix trailing comma, commit. |

- **JSON syntax check (before committing):** copy the file's contents into
  https://jsonlint.com/ and click "Validate". Green = safe to commit.
- **For anything else:** contact the website developer.
